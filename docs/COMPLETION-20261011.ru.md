# Explorer: завершение проверенных программных доработок 11 октября

Это продолжение существующей установки Jetson, заводского `robotio`, прежней
раскладки ручного управления и простого обучения. Прошивка не меняется.
Исходная точка возврата — Git `f34746d2af00c27cfeeb0dea052dcbc12adbf761`.

## Законченные исправления

| Путь | Исправление и практический результат |
| --- | --- |
| Зрение носка | Однотонная ткань с достоверной глубиной доступна для неподвижного осмотра даже без текстурных особенностей. После движения нужна новая ассоциация; статический трекер отклоняет движение до первой публикации. |
| RGB-D | Проверяются времена RGB/depth (разница до 40 мс), совпадающие размеры и неизменная калибровка. |
| Скорость обработки | Геометрия одного кадра вычисляется один раз; повторно используются только лучи с теми же intrinsics. Кэш RGB-D обновляется по поступлению кадров независимо от распознавания. Возраст и допустимый сдвиг времени не увеличены. |
| Передача камеры | Ожидание объединённого пакета SDK отключено; только камера и зрение используют общую память Fast DDS. Передача команд контроллеру остаётся на прежнем UDP-профиле. |
| Сопровождение взглядом | Первый выбранный кадр содержит необходимые координаты и intrinsics; центрирование требует пяти разных кадров. Смена камеры или калибровки прекращает сопровождение. |
| Постоянная память | Два одноимённых объекта одного кадра не сливаются; новая карта и разворот сохраняются как новый обзор; направление около ±π объединяется по кругу. |
| Результаты действий | Агент сохраняет начало, завершение, отказ и отмену в существующей semantic/episodic памяти. Только реально новый эпизод может стать наблюдением после действия. |
| Обычные команды | Без LLM доступны восстановление обзора носка, поездка к точному сохранённому месту и возврат, обход мест с отчётом, исследование с отчётом и история действий. Команда доставки вызывает прежний проверяемый исполнитель. |
| Инструкции в агенте | «Как обучать брать носок» находит шаги в установленной инструкции, показывает источник и открывает его. Поиск ограничен восемью инструкциями; текст не превращается в разрешение на движение. |
| Остановка | Команда STOP отправляется до записи журнала и независимо отменяет всех владельцев движения. Ошибка одного владельца не мешает остановке остальных. |
| Простое обучение | Повреждённый показ завершается с отрицательной оценкой пригодности, освобождая запись. SHA задания включает фактические JPEG; отсутствующие и внешние кадры отвергаются. Для испытания выбирается самый новый проверенный кандидат по времени. |
| Питание обучения | Отсутствующее или нечисловое напряжение откладывает обучение; восстановление питания допускает то же задание без падения очереди. |

Работающие управление, владельцы UART/камеры, Nav2/SLAM, Ruckig/MoveIt,
экран, подсветка и интерфейсы сохраняются. Само число записей не подменяет
проверку качества или физическую приёмку.

## Как пользоваться

- На главной странице выберите клавиатуру или джойстик: рука и база управляются
  вместе по действующей раскладке. Изменение скорости руки остаётся доступным.
- На странице обучения выберите навык, нажмите «Начать запись», выполните
  весь показ, остановите запись и отметьте фактический исход. Очередь сама
  подготавливает пригодные успешные показы и обучает кандидата при допустимой
  нагрузке и питании. Записи находятся в `data/mobile-demonstrations/`.
- В отдельном ИИ-агенте `/agent` можно запросить «Восстанови обзор носка» или
  «История задач». Осмотр не запускает контакт или смыкание.
- «Поезжай к месту … и вернись» принимает точное имя места текущей карты.
  При смене карты старые координаты возврата перестают быть действительными.

## Реальные границы, которые программа не выдумывает

Ранее оператор подтвердил плавный подход, зажатый носок, подъём, удержание и
возврат на неподвижном шасси. Это наблюдаемый тест, а не обученная политика
или доказательство автономной перевозки. На текущем включении автоматический
осмотр восстановил полный вид носка после ограниченных отъездов в предыдущих
проверках; контакт и перевозка в этом испытании ещё не выполнялись.

Кончики пальцев вне кадра, что проверено оператором. Номинальный поворот J5
почти не меняет положение TCP относительно камеры и не устраняет слепую
область. Новая рамка ткани после подъёма не доказывает удержание того же
предмета. Статическое сопровождение не используется как доказательство
захвата, отделения от инструмента или отпускания.

Произвольный pick-and-deliver требует пригодной независимой проверки контакта,
удержания и размещения, принятого захвата и назначения на карте. Повторная
локализация на сохранённой карте остаётся отдельной физической проверкой.
Сейчас пользовательских показов и обученных навыков нет; технический ACT
self-test с реальным обновлением весов не заменяет их.

Автоматическое выключение Jetson при критическом питании обеспечивается
root-owned helper. Оператор установил его 11 октября; работающая служба
подтвердила `automatic_shutdown_available=true`. Для восстановления этой
настройки на другой установке администратор один раз выполняет:

```sh
cd ~/Explorer
sudo bash bin/install-power-permission.sh
```

Это только установка ограниченного разрешения; команда не выключает робота.
Разрешена только команда helper без аргументов. Само выключение для проверки
не запускалось. Наличие сетевого питания Jetson не доказывает заряд аккумулятора:
в последней проверке напряжение снижалось до примерно 11,0 В, и штатная
политика питания отложила новые физические тесты.

## Проверки установленной системы

На Jetson выполнены **820 тестов**, два JavaScript-теста пропущены из-за
отсутствия Node.js и проверены на Mac в составе отдельного прогона
**23 тестов** (предшествующий прогон затронутых функций — 39). Прогон Jetson включает реальный CPU forward официальных моделей
распознавания человека. Это программные проверки, не приёмка всех навыков.

Через обычный API выполнены задача наблюдения с записью в долговременную память,
поиск инструкции и физический осмотр носка штатным `recover_object_view`.
Последняя задача `487db6885aec4113827c65cddcb51f52` нашла полный вид ткани
без ненужного отъезда; контакт, смыкание и перевозка в ней не запускались.
После исправления передачи выполнено неподвижное сопровождение текущей области
ткани: **38 измерений за 3,97 с**, максимальный промежуток 137 мс,
возраст после обработки не более 165 мс. Проверка использовала штатное окружение
служб и не отправляла движение. Это проверка непрерывности статической области,
не новый семантический поиск, контакт или удержание при движении.

Проверка времени на самой камере показала задержку глубины около 0,1 с ещё
до callback SDK. Временный запуск синхронизации вернул явный отказ SDK:
`Current device does not support frame sync!`; эта настройка не сохранена.
Отключение soft filter не устранило эту задержку; исходный фильтр возвращён.
Независимая выдача кадров SDK уменьшила задержку глубины до медианы 2,7 мс.
Далее установлен отдельный транспорт общей памяти для камеры и зрения:
прежний UDP терял около 37% изображений из-за переполнения приёмного буфера.
В итоговом восьмисекундном прогоне получены **119 RGB / 120 depth** кадров,
в кэш попали все 119 RGB, максимальный промежуток 70,4 мс, возраст кэша
не более 107,8 мс. Счётчик ошибок приёмного буфера не вырос.
Регистрация 640×480, intrinsics и доля валидной глубины около 98% сохранены.
Временные опыты выполнялись одной существующей службой камеры, без движения;
все временные service overrides удалены. Штампы времени, допустимая свежесть
и геометрия не подменялись.
