# Межроботный интерфейс: отдельная симуляция

На Explorer с одной физической машиной проверяется **виртуальная группа**, не реальная формация. Модуль `src/fleet_simulation.py` использует только стандартную библиотеку Python и не импортирует ROS, serial, сетевые транспорты или исполнитель руки. Он не принимает callback публикации. Никакое действие в этом модуле не двигает Explorer.

`FleetSimulation(fleet_id="demo", robots=[...], obstacles=[...])` создаёт до восьми виртуальных машин. У каждой уникальный `robot_id`, поза `[x, y, yaw]` в метрах/радианах и круглый габарит `radius`. Препятствия тоже задаются явно как `[x, y, radius]`. Начальное пересечение запрещено. Это плоская кинематическая модель; она не моделирует подвеску, динамику, руку или реальные лидары.

Команды/TF разделены метаданными `/simulation/fleet/demo/alpha/cmd_vel`, `/simulation/fleet/demo/alpha/tf` и собственными именами кадров каждой машины. Namespace выводится из ID; физические `/robotio`, `/explorer`, `/cmd_vel` или произвольная подстановка namespace отвергаются. Эти строки являются данными симуляции: здесь вообще нет ROS publisher. Экспорт в реальное управление не предусмотрен.

## Точки подключения

- `register(robot_id, pose, radius)` — добавить виртуальную машину; ID уникален.
- `snapshot()` — независимая копия поз, активных виртуальных команд и последних 100 событий. Всегда `simulation_only=true`, `execution_allowed=false`, `physical_publishers=0`.
- `assign({target_id: [x,y,yaw], ...})` — точное минимальное суммарное расстояние распределения задач методом динамического программирования по подмножествам. Число целей равно числу машин. Не утверждает, что маршрут свободен, и не отправляет команды.
- `formation("line" | "grid" | "v", anchor, spacing)` — геометрия формации с поворотом по yaw опорной позы; габариты и препятствия проверяются в целевых точках; затем выполняется распределение. Движение не начинается.
- `submit(robot_id, velocity, sequence, deadline, session, namespace)` — виртуальная скорость `[vx,vy,wz]` в системе корпуса. Требуются текущий случайный session, точный namespace, возрастающий номер и deadline в пределах следующей секунды симуляции. Линейная скорость ограничена 0,8 м/с, угловая 1,5 рад/с: это пределы модели, не новая настройка реальной машины.
- `advance(seconds)` — продвинуть только виртуальное время, шагами не более 20 мс. Команда действует лишь до своего срока, даже если срок попал внутрь шага. Проверяется полный отрезок перемещения относительно препятствий и относительное движение пар роботов. При пересечении весь синхронный шаг отвергается и команды отменяются.
- `cancel(robot_id=None)` — отменить виртуальную команду, не сбрасывая последний номер.
- `reset_session()` — новый session и инвалидирование всех старых команд. Сохранённый snapshot не может автоматически восстановить движение; метода загрузки активных команд нет.

Минимальная проверка без подключённого робота:

```python
from fleet_simulation import FleetSimulation

simulation = FleetSimulation(robots=[
    {"robot_id": "alpha", "pose": [0, 0, 0]},
    {"robot_id": "beta", "pose": [2, 0, 0]},
])
plan = simulation.formation("line", [4, 0, 0], spacing=0.8)
simulation.submit("alpha", [0.2, 0, 0], 1, 0.5,
                  simulation.session, simulation.robots["alpha"]["namespace"])
result = simulation.advance(1)
assert result["robots"]["alpha"]["pose"][0] < 0.101
assert not result["active_commands"]
```

`PYTHONPATH=src python3 -m unittest discover -s tests -p test_fleet_simulation.py` проверяет ID/TF, отказ физических namespaces, отсутствие транспорта, сроки/replay/session, распределение, формации и столкновения. Это компьютерные проверки; реальные несколько машин не испытывались.

## Существующее планирование руки

`src/arm_planner.py` и отдельный worker/client строят OMPL-траекторию MoveIt с явным исходным состоянием, коробками препятствий и независимой проверкой коллизий. Результат содержит точки рассчитанной траектории, а не только конечную позу. `src/arm_library.py` предоставляет сохранённые сцены/позы, `preview_joint`, `preview_named`, `preview_cartesian` и ограниченный `preview_random`. Cartesian-проверка дополнительно отвергает OMPL-путь, вышедший из коридора запрошенной линии. Все эти результаты остаются предпросмотром: они не подтверждают физическое достижение. Эти функции не связываются с симуляцией группы и не переписываются ради неё.
