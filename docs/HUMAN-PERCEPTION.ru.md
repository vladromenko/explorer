# Человек, кисть и жесты: вычислительный компонент Explorer

`src/human_perception.py` выполняет пассивное распознавание по уже сохранённому кадру бортовой камеры. Модели загружаются только по запросу; отдельной службы, владельца камеры, подключения к UART и отправки движений здесь нет. Исходный web и простое обучение не меняются этим модулем. Подключение новых кнопок/навыков делает общая панель через штатный исполнитель.

## Что действительно распознаётся

| Режим | Вычисление | Результат |
|---|---|---|
| `hand` | официальный MediaPipe Palm Detector → собственное декодирование SSD → повёрнутая область → официальный HandPose | 21 ориентир кисти, уверенность, модельное handedness, геометрические признаки раскрытых пальцев |
| `pose` | официальный MediaPipe Person Detector → повёрнутая область тела → Pose | 33 ориентира тела, visibility/presence; 6 вспомогательных точек модели не выдаются за суставы |
| `face` | официальный OpenCV YuNet | 5 ориентиров: глаза, нос, уголки рта. Это **не** 468-точечная face mesh и не узнавание личности |
| Жесты | консервативная геометрия по настоящим 21 ориентирам | открытая ладонь, кулак, указание, щипок либо `neutral`; направление указания в плоскости изображения |
| Рисование | указательный палец в явно включённом контексте | до 256 нормированных 2D-точек на изображении; это **не** готовая траектория руки |

Все координаты `landmarks` — пиксели исходного кадра. Для кисти `z` — относительная оценка модели; для тела массив имеет `[x,y,z,visibility,presence]`. `z` не является измерением RGB-D или метрической позой относительно робота. `bbox` лица имеет формат `xyxy`. Глубина, hand-eye, достижимость и коллизии остаются ответственностью общих измерителей/исполнителей.

Порог landmarks: 0,8. Слишком маленькая кисть и неоднозначное положение пальцев дают `neutral`. Однотонное изображение не считается достоверным лицом. Ошибка загрузки модели или её выполнения возвращается в `errors` конкретного режима, без нулевого скелета или skin/bounding-box заглушек.

## Установка официальных моделей

На Jetson из каталога проекта:

```bash
python3 bin/install-human-models.py --check-runtime
```

Повторная проверка без сети:

```bash
python3 bin/install-human-models.py --verify --check-runtime
```

Установщик скачивает только фиксированные официальные файлы и их лицензии в `models/human-perception/`, проверяет размер и SHA256 по Git LFS, сохраняет `manifest.json`. Около 26 МБ оригиналов, плюс примерно 22 МБ совместимых файлов для OpenCV 4.6. Он не устанавливает pip-пакеты, не заменяет рабочий OpenCV, не открывает камеру и не запускает сервисы. HTTPS-проверка сертификатов сохраняется.

Модели Palm/Hand/Person/Pose — Apache 2.0. YuNet — MIT. Лицензии скачиваются и проверяются отдельными фиксированными хэшами. Производитель робота и его прикладной код не использованы. Собственное предварительное преобразование и декодирование ориентируются на опубликованный контракт моделей OpenCV Zoo.

## Совместимость с имеющимся OpenCV 4.6

Штатные ONNX 2023 не импортируются целиком в OpenCV 4.6: его `Clip`/`Squeeze` ожидают один вход, а `Gemm(transB=0)` неправильно определяет число выходов. Рабочий стек ради этого не заменяется.

Установщик воспроизводимо создаёт отдельные `.cv46.onnx`: константы `Clip(0,6)` и `Squeeze` переносит в атрибуты старого importer; четыре `Gemm` кисти с `transA=transB=0` раскладывает в математически эквивалентные `MatMul+Add`. Весовые тензоры и оригинальные файлы сохраняются. Конвертер принимает только проверенные исходные SHA и проверяет заранее зафиксированные SHA результата и число замен: Hand 37, Person 32, Pose 68. Это **диалект importer OpenCV 4.6**, а не универсальная корректная миграция opset для произвольного ONNX Runtime. Новый OpenCV 4.8+ получает оригиналы. YuNet: 2022 для 4.6, 2023 для 4.8+.

В каждом результате `runtime_models` раздельно показывает исходный SHA модели и SHA фактически загруженного файла. Для восстановления достаточно установщика и исходников; совместимые бинарники не требуется хранить в Git.

## Контракт интеграции

```python
from human_perception import HumanPerception, GestureGate
human = HumanPerception(ROOT)
result = human.observe(modes=("hand",))
# Или уже декодированный общий кадр:
result = human.analyze(bgr_image, image_stamp, ("pose", "face"), frame_id)
human.unload()  # освобождает загруженные сети
```

`observe()` проверяет `camera-frame.json`, SHA текущего `frame-raw.jpg` и свежесть до 0,7 с. `analyze()` дополнительно помечает результат `stale`, если он устарел за время вычисления. Изображение до 1280 пикселей по большей стороне. Сети сериализованы локальным lock; вызов не создаёт потоков/фонового бесконечного inference. Планировщик может выбирать один нужный режим, чтобы сохранять бюджет вычисления.

Пассивный результат всегда содержит `motion_authorized=false`. Увиденный человек не может сам разрешить управление.

```python
gate = GestureGate()
gate.begin(
    session_id="authenticated-operator-session",
    mapping={"open_palm": "wave", "fist": "nod"},
    operator_region=[x1, y1, x2, y2],
    expires_s=20,
    physical_authorized=operator_observing,
)
proposal = gate.update(result)
gate.cancel()
```

`begin()` вызывается только после отдельного явного действия оператора: выбранная область его кисти, разрешённая группа, ограниченный срок. `physical_authorized` не выводится из жеста, модели или наличия человека. Внутри allowlist: `look_left/right/up/down`, `open_gripper`, `close_gripper`, `wave`, `nod`, `trace_2d`. Никаких команд шасси и произвольного кода.

Для предложения нужны ровно одна достоверная кисть в выбранной области, несколько новых последовательных кадров и устойчивый жест не менее 0,25 с. Повтор одной позы подавляется до нейтрального состояния. Старый/повторный кадр, пропавшая/неоднозначная кисть и истечение контекста не дают предложений. Proposal имеет ID, срок до 0,5 с, session ID, действие и `requires_executor_validation=true`; модуль сам его не исполняет. Общий исполнитель повторно проверяет разрешение оператора, ресурсы, текущую руку/камеру и допустимый навык. Для `trace_2d` даже разрешённый контекст выдаёт только линию на изображении, без движения.

## Что проверено

18 компьютерных тестов: разрешение/срок/нейтральность, повтор/порядок/свежесть кадров, отсутствие и неоднозначность человека, ограниченный рисунок, невалидные ориентиры, отсутствие модели/неверный SHA, отсутствие загрузки при создании объекта, настоящие tensor shapes и CPU forward.

В отдельном временном каталоге Jetson выполнены все 18 тестов на существующем `.venv`/OpenCV 4.6. Все пять сетей проходят offline forward. На официальных примерах OpenCV Zoo/OpenCV, без обращения к камере робота: кисть 21 ориентир, confidence 0,9855, 166 мс; тело 33 ориентира, confidence 1,0, 212 мс; лицо 5 ориентиров, confidence 0,9995, 23 мс. Это единичные примеры, не доказательство точности на текущей комнате или измерение постоянного FPS. Проверка камеры и разрешённых физических групп — отдельная интеграционная приёмка. Сервисы и движения при этих проверках не менялись.

Запуск тестов без скачанных моделей: `python3 -m unittest discover -s tests -p test_human_perception.py` (17 обычных тестов и один явно пропущенный model-forward). С установленными моделями: `TEST_HUMAN_MODEL_DIR=models/human-perception python3 -m unittest discover -s tests -p test_human_perception.py`.
