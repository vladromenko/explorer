# ИИ-агент и навыки Explorer

Отдельная страница: `http://explorer.local:8080/agent`. Код доступа тот же, что в прежней панели; мобильное открытие также работает по LAN или разрешённому Tailscale-адресу. Прежние управление и обучение доступны по ссылке наверху и сохраняют свою раскладку.

## Начать

1. Откройте страницу и введите код доступа, если он не сохранён в текущем сеансе браузера.
2. Напишите «Посмотри влево», «Найди носок и остановись», «Исследуй комнату», «Где ты последний раз видел бутылку» либо выберите готовый навык и заполните его параметры.
3. Нажмите **Показать план**. Для навыка из каталога нажмите **Добавить навык в план**.
4. Проверьте последовательность. Для физического движения подготовьте область и подтвердите наблюдение галочкой.
5. Нажмите **Выполнить план**. Справа появятся фактические этапы, аргументы, длительности по журналу и результат.
6. **Отменить задачу** отменяет текущую задачу. **СТОП** вызывает прежний немедленный путь остановки, обходя модель.

Кнопка **Сказать команду** использует установленный микрофон робота и локальное ASR. Проверьте распознанный текст перед показом плана. Запись речи самостоятельно не разрешает движение. **Прервать звук** вызывает существующий путь прерывания аудио.

## Готовые сценарии

При первом запуске добавляются только совместимые сценарии: текущее наблюдение и состояние, обзор камерой, найти носок и остановиться, исследовать и показать отчёт. Они исполняются без LLM. Сценарий «Восстановить обзор носка» добавляется также к существующей библиотеке, сохраняя старые версии и пользовательские сценарии. Он сам осматривает пол и при необходимости отъезжает на 6 см, не более двух раз; новое обнаружение не запускает захват. Сценарий поиска по умолчанию осматривает текущую область; чтобы посетить другие места, добавьте их точные имена в `places`.

Сценарии содержат до 12 шагов. Редактор сохраняет новую версию, сохраняя старую. Запущенная задача получает неизменяемую копию плана. Условия разрешены только по наблюдаемым `state`/`found` предыдущего шага, например:

```json
{"steps":[
  {"skill":"detect_objects","args":{"label":"sock"}},
  {"skill":"observe_scene","args":{},"if_result":{"step":0,"field":"found","equals":true}}
]}
```

Для построения и сохранения карты выберите `explore_area`, заполните `map_name` новым ASCII-именем и ограничьте `max_goals`. Это существующий frontier-исполнитель с камерой и возвратом, не обещание полного обследования квартиры. Для обхода выберите `follow_route` и точные сохранённые имена. Доставка использует уже существующую проверенную цепочку DeliveryTask; если приёмка/предмет/назначение не подходят, показывается причина. Произвольные предметы и сортировка не объявляются готовыми только потому, что модель составила план.

## Значение результата

| Состояние | Значение |
| --- | --- |
| accepted | Запрос сохранён, физический результат ещё отсутствует |
| running | Реальный исполнитель выполняет указанный шаг |
| waiting | Не выполнено конкретное условие или исполнитель отклонил запрос; повтор сам не запускается |
| succeeded | Зарегистрированный исполнитель вернул доказательства своего завершения |
| unknown | Отправка/истечение команды завершились, физический результат недостаточно подтверждён |
| failed | Исполнение или срок завершились ошибкой |
| cancelled | Поколение отменено; поздние результаты не оживляют команду |
| interrupted | Служба перезапущена; старое задание автоматически не возобновляется |

Произвольное `move_arm` с command-only `robotio` может завершить рассчитанный путь, но состояние агента остаётся `unknown`, если реального достижения не измерено. Специальный `look_direction` имеет другой наблюдаемый контракт: законченная команда обзорной позы, принятая привязка камеры и новый кадр после стабилизации. При `phase=ready` такой осмотр завершён и следующий `observe_scene`/`detect_objects` выполняется; суставы при этом всё ещё `measured_joints=false`, координаты остаются оценочными. Он не подтверждает контакт или точность произвольного движения. Это не отменяет ручное управление. Такой результат останавливает оставшиеся зависимые шаги сценария. Открытие/закрытие J6 не считается контактом, измеренной силой или успешным захватом. Память возвращает время и место наблюдения; прошлое наблюдение не считается наличием предмета сейчас.

## Реализация

- `src/onboard_agent.py`: небольшой worker, SQLite, типизированный allowlist, неизменяемые планы, поколения, сроки, идемпотентность и версии сценариев. База `data/onboard-agent.sqlite3` добавлена отдельно, старые базы не мигрируются.
- `src/agent_ports.py`: явные адаптеры к NavigationTasks, Missions, ObjectFinder, CameraViews, TrajectoryExecution, DeliveryTask и SemanticWorld. Нового владельца UART, камеры и моторов нет. Один worker исполняет шаги последовательно; аппаратные условия и блокировки существующих исполнителей остаются обязательными.
- `src/agent_intent.py`: обычные шаблоны независимы от модели; свободные формулировки идут в уже установленный локальный llama.cpp на `127.0.0.1:8081`. Ответ модели всегда проверяется как ограниченный JSON-план. Модель не назначает права, не снимает STOP, не запускает shell/eval и не генерирует двигательные команды на каждом такте.
- `src/agent_api.py`: защищённый REST/OpenAPI, ограниченный поток событий и тонкий MCP-адаптер к тому же каталогу.
- `src/agent.html`, `src/agent-ui.js`: отдельная страница с камерой, планом, каталогом, голосом, историей и редактором небольших сценариев.

Ресурсоёмкий поиск и LLM используют прежние механизмы загрузки и resource profiles. Внешние модели, Dify, Redis, отдельная векторная БД и постоянный Mac не нужны. Свободный запрос при недоступной локальной модели показывает конкретную ошибку; готовый каталог и сценарии продолжают работать.

## API и MCP

Все `/api/skill-agent/*` требуют прежний Bearer-код, проверяют Origin и не публикуют секреты. `/api/skill-agent/openapi` выдаёт машинный контракт; ссылка в интерфейсе скачивает JSON с уже пройденной авторизацией. Запуск `POST /api/skill-agent/tasks` принимает `request_id`, `plan`, `observing`, `ttl_s`. Повтор с тем же request_id возвращает прежнюю задачу и не повторяет действие; изменение плана с прежним ID отклоняется.

`GET /tasks/{id}` возвращает журнал и доказательства, `GET /tasks/{id}/events` — ограниченный SSE-поток, `POST /tasks/{id}/cancel` — отмену. До 2 минут сохраняется SSE-соединение; далее клиент может переподключиться или читать статус. Сохранённая фотография object-search привязана к ID наблюдения в доказательствах задачи; история не показывает вместо неё последний кадр другого поиска.

MCP `POST /api/skill-agent/mcp` поддерживает stateless JSON-RPC initialize/ping/tools/list/tools/call для версии `2025-03-26`. Основа: [официальная спецификация MCP](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/schema/2025-03-26/schema.ts). Инструменты возвращают task_id, а `get_task` показывает результат. Это тонкий транспорт, а не дополнительный исполнитель.

Модель внешнего MCP-клиента не может выдумать `observing=true`. Для физического инструмента оператор отдельно выдаёт разрешение через защищённый `POST /api/skill-agent/mcp-permission/{skill}` с телом `{"observing":true}`; непрозрачный `authorization_id` действует 120 секунд для одного skill и одного request_id. Разрешение не переживает перезапуск. Для обычной работы используйте страницу агента; будущий внешний клиент обязан показывать такой запрос оператору. Получение MCP-разрешения не снимает STOP и не меняет механические ограничения.

## Проверка и границы

`tests/test_onboard_agent.py` проверяет реальные условия программного слоя: стабильный request_id, неизвестные навыки, NaN/bool, запрещённое самоназначение прав, поколения отмены, поздние результаты, сроки, отсутствие replay после рестарта, неизменяемость сценария, UNKNOWN и сохранение пяти суставов при J6. Эти тесты не доказывают движение, захват или навигацию физического робота. Физическая приёмка каждого навыка записывается отдельно в общий журнал выпуска.

## Завершение агентного слоя, 11 октября 2026

Готовые команды теперь покрывают составные маршруты без LLM: «Поезжай к месту Дверь и вернись», «Обойди сохранённые места и покажи отчёт», «Исследуй комнату и покажи отчёт», «Восстанови обзор носка», «История задач», «Возьми носок и положи в место Корзина» (точное имя принятого назначения). Последняя команда составляет план к существующему `deliver_object`; она не выдаёт приёмку доставки и не запускается до проверки исполнителем. Название места берётся из текущей карты; неизвестное место вызывает одно уточнение. Поездка с возвратом запоминает наблюдаемую исходную позу, исполняет оба пути через прежний NavigationTasks/Nav2 и проверяет неизменность map epoch. Неудачный путь туда не запускает слепое возвращение. Возврат в предварительной карте не объявляется измеренной абсолютной точностью.

Каждый реально начатый навык агента и его фактический исход сохраняются в существующей `SemanticWorld`: задача, навык, аргументы, состояние, evidence, предыдущий эпизод и новый эпизод после действия, если он действительно появился. При отсутствии нового кадра `after_episode=null`; старое наблюдение не выдаётся за результат движения. `unknown`, ожидание условия, ошибка и отмена не превращаются в успешный захват. Ошибка записи памяти отмечается в журнале агента и не меняет уже полученный результат исполнителя. Навык `query_task_memory` возвращает последние 1–50 записей. Это episodic/action memory в SQLite; обучение весов запускается отдельным прежним учебным процессом.

Исправлены три воспроизводимых дефекта семантической памяти: два одинаково подписанных объекта одного кадра больше не обновляют одну и ту же entity; наблюдение после смены карты или значительного разворота не подавляется как прежний неизменный вид; среднее направление около ±π вычисляется по кругу. Пространственное соответствие entity остаётся гипотезой по измеренной map-точке, а не доказательством физической идентичности.

**DONE по реализации:** защищённый реестр и worker, отмена/сроки/идемпотентность, локальные offline команды и версия сценариев, вызовы существующих MoveIt/Nav2/зрения, просмотр текущего плана и реального журнала, экспорт сохранённых осмотров, ограниченная семантическая и episodic память, локальный ASR и прерывание звука, OpenAPI и MCP к одному исполнителю. Вызовы семейства глубины, цвета, AprilTag, человека, отслеживания ROI, визуального движения, сцен руки и симуляции формации уже зарегистрированы прежними адаптерами; новые независимые владельцы оборудования не добавлены.

**PARTIAL по физическому результату:** произвольный pick-and-deliver и сортировка зависят от принятой геометрии, контакта, удержания и места размещения; LLM-план не открывает их фиктивно. На command-only суставе истечение пути не является измерением. Общий подсчёт инвентаря по нескольким кадрам не подтверждён без надёжной идентичности объектов. **MISSING по оборудованию:** реальная формация нескольких роботов; на одном Explorer доступна отдельная симуляция и интерфейс. Внешние Dify/OpenClaw не нужны для этих действующих путей.

## Вопросы к действующим инструкциям без LLM

На странице **«ИИ-агент и навыки»** напишите «Как обучать брать носок», «Как строить карту», «Инструкция по клавиатуре и джойстику» либо выберите `query_instructions` в каталоге. Нажмите **Показать план**, затем **Выполнить план**. Это чтение документов: подтверждение наблюдения и движения не требуются. Результат показывает выдержку, раздел, исходный файл и строку; **Открыть полный источник** загружает весь действующий документ с той же авторизацией. Если источник изменился после задачи, интерфейс явно сообщает об обновлении. Явное «Стоп» по-прежнему вызывает штатный STOP; вопрос «Как снять стоп» лишь ищет инструкцию.

`src/instruction_knowledge.py` читает только восемь заранее разрешённых документов: `TRAINING-GUIDE.ru.md`, `MANUAL-CONTROLS.ru.md`, `ROOM-EXPLORATION.ru.md`, `ONBOARD-AGENT.ru.md`, `LEARNING-IMPLEMENTATION.ru.md`, `MOBILE-REMOTE.ru.md`, `ROBOT-TEXTBOOK.ru.md`, `EXPLORER-ONBOARD-RELEASE-20261010.ru.md`. Поиск использует ограниченные лексические совпадения, явные русские/английские варианты терминов, заголовки и темы документов. Это простой offline retrieval существующего operator knowledge, без векторной БД, дополнительных моделей и обучения весов.

Запрос — до 300 символов, ответ — до пяти источников, один раздел на документ, выдержка до 1800 символов; документ — до 256 КБ. В ответе есть SHA256 реально прочитанного источника. `GET /api/skill-agent/instructions/{document_id}` принимает фиксированный ID, проверяет прежнюю Bearer-авторизацию и не допускает произвольного пути, конфигураций или секретов. Текст отображается через `textContent`, без выполнения HTML, shell или инструкций из документа. Retrieved text имеет `execution_authority=false`, не открывает приёмку и не формирует двигательных действий. Новая запись руководства сама по себе не меняет поведение приводов.
