# Наблюдения, экспорт и пассивное наблюдение зоны

`src/scene_reports.py` дополняет существующий `SurveyStore`, не меняя его сохранённые записи и не отправляя команды движения. Отчёт работает с реальными осмотрами `data/surveys/<mission>/*.json`. Гипотезы детектора не выдаются за проверенную инвентаризацию.

## Экспорт осмотра

```python
from scene_reports import SceneReports
reports = SceneReports(root)
result = reports.export(mission_id)
```

`export()` создаёт новый постоянный каталог `data/scene-reports/<id>` с `report.json`, `report.csv`, `report.html` и копиями фактически сохранённых изображений. Результат содержит `id`, полный `report` и относительные пути `artifacts`. HTML открывается отдельно, содержит реальные кадры и их происхождение; CSV представляет одну строку на гипотезу в одном наблюдении. В каждом наблюдении сохраняются место, время, поза робота, эпоха карты, исходный JSON и его SHA256. Каждое изображение имеет SHA256 и путь источника. Отсутствующие/повреждённые файлы отражаются в `record_errors`, без выдуманных изображений.

У нынешнего `SurveyStore` `context_image_same_frame_verified=false`: JPEG — настоящий контекст осмотра, но его точное совпадение с кадром детекции не доказано. Экспорт сохраняет этот флаг. Смена имени или копирование файла не превращает контекст в синхронизированный кадр.

`scene_composition(perception)` возвращает `per_frame_hypothesis_counts`, цвет/форму/visual-tag при их наличии и исходный `image_stamp`. `identity_status="unknown"`, `physical_item_count=null`, `deduplicated_inventory_verified=false`. Две фотографии одного носка остаются двумя наблюдениями; из них не получается «два носка». Надписи, принадлежность предмета и смысл visual-tag не выдумываются.

Для существующего HTTP API сервер может вернуть ссылки на защищённый endpoint и обслужить файл через `reports.artifact(id, filename)`. Метод возвращает проверенный `Path`, допускает только три формата отчёта и изображения `N.jpg`, отвергает выход из каталога/подмену symlink. Endpoint должен сохранять нынешнюю авторизацию, не принимать произвольный путь с клиента. HTML экранирует текст источников, CSV защищён от формул в текстовых полях. Экспорт ограничен 2000 записями; JSON — 2 МБ, изображение — 8 МБ.

## Пассивное наблюдение выбранной зоны

```python
from scene_reports import ZoneWatch
watch = ZoneWatch()
rgb, jpeg, metadata = onboard_vision.frame()
watch.begin(jpeg, metadata, reference, [x1, y1, x2, y2])
# При следующем действительно новом кадре:
rgb, jpeg, metadata = onboard_vision.frame()
result = watch.compare(jpeg, metadata, updated_reference)
watch.cancel()
```

Кадр берётся у существующего владельца камеры через `OnboardVision.frame()`. Новый владелец камеры, поиск направления или движение руки не создаются. ROI задаётся в пикселях фактически показанного кадра; размер каждой стороны не меньше 12 пикселей. Нужно оставить текстурный контекст вокруг зоны.

`reference` — снимок известного состояния, сформированный существующим control/status адаптером:

```json
{
  "at": 1791630000.1,
  "arm_deg": [90, 90, 90, 90, 90, 159.5],
  "base_pose": [0.2, 0.4, 0.1],
  "stationary": true,
  "reference_valid": true,
  "calibration_id": "actual-current-calibration-id",
  "map_epoch": "actual-current-map-epoch"
}
```

Пример показывает формат, а не готовое состояние робота. Адаптер берёт фактическую свежую позу и принятую калибровку; `stationary` проверяется по состоянию движения базы и руки. Недоступную локализацию или неизвестную исходную позу нельзя подменять нулями/`reference_valid=true`. При command-estimate руки этот источник остаётся оценкой; пассивная проверка не делает его encoder feedback. Не используйте timestamp последней старой команды как свежесть текущего состояния.

Проверяются SHA256 JPEG, `same_frame_hash_verified`, `frame_id`, camera ID, camera-info version, optical frame, свежесть кадра/состояния до 0,8 с и их разница до 0,4 с. Сравнивать можно только новый кадр в течение 60 с от выбранного исходного; повторные ID/время отвергаются. Хранятся только исходный и последний кадры. Максимальный декодированный кадр — 2,1 млн пикселей.

Если arm pose изменился больше 0,3°, база сместилась больше 1,5 см/0,02 рад, изменились калибровка, эпоха карты или камера — требуется новая исходная зона. Пустые/однотонные кадры отвергаются. Phase correlation по контексту вне ROI дополнительно отвергает незаявленное смещение камеры больше двух пикселей и плохое совпадение. Gaussian blur уменьшает шум; медианный сдвиг яркости вне ROI компенсирует небольшое общее изменение освещения. В зоне считается доля пикселей с изменением яркости больше 18; от 4% результат `phase="changed"`, иначе `unchanged`.

Результат содержит оба ID/хэша изображений, ROI, свежую camera/reference provenance и `motion_requested=false`. Это гипотеза визуального изменения, не доказанное появление/исчезновение конкретного предмета. Сигнал можно показать или сохранить существующим агентом; автоматическое движение из этой проверки не запускается.

## Проверки

`PYTHONPATH=src python3 -m unittest discover -s tests -p test_scene_reports.py` проверяет экспорт реальных тестовых JPEG, сохранение разделения кадров, повторные ракурсы без выдуманного инвентаря, escaping/path safety, новые/повторные кадры, реальные изменения изображения, общую яркость, сдвиг камеры, движение руки/базы, пустые и недоступные кадры. Эти компьютерные проверки не считаются физической приёмкой наблюдения квартиры.
