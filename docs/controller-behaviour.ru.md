# Контроллер ROSMASTER M3 Pro: проверенные возможности

Проверено на Explorer 28 сентября 2026 года. Прошивка платы не изменялась.
Пользователь повторно подтвердил запрет на её изменение; дальнейшие работы выполняются в пределах этого ограничения.

## Два разных разрыва связи

Джойстик передаёт намерение оператора Jetson. При прекращении команд ручного управления Jetson отправляет нулевую скорость через 250 мс. Навигация имеет собственные команды и разрешение с ограниченным сроком действия; присутствие джойстика ей не требуется.

Плата двигателей получает скорость от Jetson по отдельному соединению USB / micro-ROS. В [штатном уроке ROS Control](https://github.com/YahboomTechnology/ROSMASTER-M3PRO/blob/main/01.Chassis%20Control%20Course/1.ROS%20control.pdf) Yahboom описывает однократную отправку скорости и отдельную отправку нуля для остановки. Отсутствие сообщений само по себе не является командой остановки. Это относится и к ручным, и к автономным командам.

В доступном учебном примере `Subscriber_twist` есть опрос агента и остановка после выхода из цикла. Нельзя считать его тождественным полной заводской прошивке: сохранённый образ Explorer имеет другой цикл обработки. Физические тесты паузы агента 1,046 и 2,251 с ранее не подтвердили ограниченную остановку двигателей; разбор образа сохранён в `config/controller-readback-audit.json`.

Исправление от 28 сентября: потеря свежей одометрии или напряжения теперь завершает сессию управления Jetson, сбрасывает автономный режим, отзывает разрешение навигации и фиксирует STOP. Возвращение телеметрии не снимает STOP. Это устраняет автоматическое возобновление после разрыва, но не доставляет команду отключённой плате. Независимый процесс `watchdog.py` также отправляет ноль, если основной процесс управления перестал отвечать; ему тоже нужен исправный канал до платы.

Проверка этого изменения без движения:

```bash
cd /home/vlad/Explorer
source bin/env.sh
python3 bin/check-stationary-link-recovery.py
# Реальная пауза агента, только после завершения всех движений:
python3 bin/check-stationary-link-recovery.py --execute-stationary-test
```

Сценарий не посылает ненулевой скорости. Он проверяет завершение программной сессии после паузы агента на 0,85 с, сохраняет `data/mcu-stationary-link-audit.json` и требует заново подготовить руку после прерывания её телеметрии. Это не испытание аппаратного торможения и не разрешение автономной езды.

Фактический запуск прошёл: пауза 0,8504 с, после восстановления режим MANUAL, STOP зафиксирован, все три скорости нулевые. Ненулевые команды в этом тесте не отправлялись. После теста рука повторно подготовлена под камерой.

## Что известно об аккумуляторе

В [описании платы](https://github.com/YahboomTechnology/ROSMASTER-M3PRO/blob/main/18.Control%20Board%20Course/1.Development%20environment%20setup/1.Introduction%20to%20the%20Control%20Board/1.Introduction%20to%20the%20Control%20Board.pdf) для батареи указан вход PC0 / ADC. [Урок измерения напряжения](https://github.com/YahboomTechnology/ROSMASTER-M3PRO/blob/main/18.Control%20Board%20Course/2.Control%20board%20STM32%20basic%20routine/5.Battery%20voltage%20detection/5.Battery%20voltage%20detection.pdf) использует выражение `ADC × 3.30 / 4096 × 4.03`.

На работающем Explorer узел `/robotio` публикует `/battery` типа `std_msgs/msg/Float32`: напряжение в вольтах. В его текущем ROS-интерфейсе нет публикации тока батареи, накопленного заряда, SOC или состояния зарядника; сервисов запроса этих данных также нет. Наличие типа `BatteryState` среди общих библиотек micro-ROS не означает наличие таких измерений у платы.

Поэтому экран показывает измеренное напряжение и явно приблизительную шкалу `V≈%`. Она не превращается в фактический процент заряда после подключения зарядника. Для обоснованного SOC нужна характеристика конкретной батареи и соответствующие измерения либо телеметрия отдельного измерителя заряда; [TI описывает различия методов оценки](https://www.ti.com/product-category/battery-management-ics/battery-fuel-gauges/overview.html). Потребление Jetson не равно току всего робота.

Во время этой сессии после подключения питания напряжение поднялось примерно с 11,26 до 11,46 В и удерживалось при работе руки. Это наблюдение напряжения, а не подтверждение тока зарядки или полного заряда.

## Повторная проверка шасси

Под наблюдением выполнены шесть импульсов по 0,7 с: поступательные 0,05 м/с и вращательные 0,18 рад/с. Оценка перемещения в системе корпуса по штатной одометрии:

| Команда | Основное перемещение | Скорость после остановки |
| --- | ---: | --- |
| Вперёд | +16,34 мм | нулевая |
| Назад | −17,07 мм | нулевая |
| Влево | +1,97 мм | нулевая |
| Вправо | −7,90 мм | нулевая |
| Против часовой стрелки | +2,10° | нулевая |
| По часовой стрелке | −0,78° | нулевая |

Разница сторон в этой короткой пробе не является готовым коэффициентом калибровки. Данные содержат переходный процесс разгона, а не установившееся движение. Видео Logitech использовалось для наблюдения, лидары — для проверки свободного пространства. Сохранённые журналы: `data/base-probe-*-20260928-04*.json`.

Эти результаты подтверждают отклик направлений и остановку по доставленной команде. Они не доказывают точность перемещения на метр, удержание предмета, доставку или остановку при обрыве USB.
