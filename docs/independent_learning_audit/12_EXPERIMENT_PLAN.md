# 12. Минимальные различающие эксперименты до выбора архитектуры

**Это план, не журнал выполненных экспериментов.** Аудит не запускает train/rollout наугад. Исключения, действительно выполненные read-only: inventory, hashing, сохранённый input replay, thumbnail/sample analysis. Их результаты находятся отдельно. Любое новое действие с настоящими приводами требует отдельного разрешения.

Общие правила: неизменяемый source, раздельный output, заранее фиксированные seeds/лимиты/метрики, сохранение failures; одинаковые scenes для A/B; финальные holdout не используются для выбора. Тайм-аут и отсутствие доказательства не считаются успехом. Стоимости ниже — инженерные оценки, **HYPOTHESIS**, а не измеренные обещания.

## Последующий конкурс методов

Только после A–F: ACT / простой BC / Diffusion Policy на одинаковых данных и runtime. Для RL отдельно построить MDP: реально наблюдаемый state, action и исполнение совпадают, reward независим после действий, terminals/truncations точны. Затем ограниченный SAC/RLPD или PPO pilot. Нельзя сравнивать миллионы RL steps с другим количеством expert-target кадров без учёта walltime и стоимости данных.

Нужны не менее трёх train seeds на метод для выбора, общие development scenes, success interval, collisions, unsafe outputs, correction yield, idle ratio, симулированные часы/gradient updates/реальные часы отдельно. Исторические final scenes исключаются; новый конкурс не подменяет текущую приёмку 100 полных миссий.

Сначала измерять зависимость и исправлять контракт, затем алгоритм. Если teacher не проходит, немедленный переход на более крупную VLA не является обоснованным исправлением.
