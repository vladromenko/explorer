# Аудит Explorer — 8 октября 2026

Исходная версия: `4325562` (`Make experiments actionable and show live dual-lidar mapping`). Точка возврата в Git: `pre-full-audit-20261008`. Проверена текущая копия на Mac и действующая установка `/home/vlad/Explorer` на Jetson. Аудит и тесты выполнялись без команд движения и без записи STM32.

## Подтверждённые ошибки и исправления

| Приоритет | Причина | Исправление | Доказательство |
|---|---|---|---|
| P1 | `autonomy_runtime.record_scorer_sample()` использовал `PolicyVersion` без импорта. На 20-м подходящем примере возникал `NameError`. | Добавлен импорт; кандидат регистрируется без автоматического принятия. | Регрессия с 20 эпизодами и проверкой состояния `candidate`. |
| P1 | `AutonomySupervisor.process()` всегда завершал серию как `succeeded`, включая неудачу и неизвестный результат. Обработка позднего результата могла перезаписать отмену. | Итог соответствует результатам; отмена сохраняется; отдельный счётчик инфраструктурных ошибок. | Проверены success, failure, unknown, infrastructure_error, cancelled и отмена пользователем внутри исполнительного вызова. |
| P1 | `web.autonomy_action()` не передавал предмет и место назначения исполнителю. Узкий сценарий носка мог исполниться вместо другого запроса. | Неизменяемая копия запроса передаётся до `DeliveryRobot.begin()`. Предмет и место проверяются после загрузки принятой конфигурации и до первого движения. | Проверены правильные названия, чужой предмет/адрес, пустой запрос и изменение исходного словаря после запуска. |
| P2 | `index.html:loadAutonomy()` вставлял вопросы/варианты помощи в `innerHTML` и строковые обработчики. | Текстовые DOM-узлы и обработчики без сборки исполняемого кода из строк. | Выполнен реальный JS с HTML-подобным текстом, кавычками и проверкой нажатия. |
| P2 | `LearningJobs.start_mobile()` возвращал прежний failed/interrupted job для того же набора показов. Повторное ручное обучение не запускалось. | Завершённые неудачные попытки можно запустить заново. Действующая или успешно законченная работа сохраняет защиту от дублей. | Проверены failed, interrupted, cancelled, rejected, queued и complete. |

Дополнительно исправлен P2-дефект диагностики: тайм-аут `systemctl is-active` давал HTTP 500 в диагностике и статусе карты. Один ограниченный пакетный запрос теперь возвращает `unknown` и причину, не выдавая недоступные данные за выключенную службу. Проверены смешанные состояния, неполный ответ, тайм-аут и отсутствие systemctl. Восстановление карты при неизвестном состоянии служб не перезапускает потенциально исправные компоненты.

Два старых теста записи показов исправлены под действующий контракт: оператор может сохранить успех, но пустая/некачественная запись не становится пригодной для обучения. Кнопки отдельных стадий не обязательны. Порог качества не ослаблен.

## Существенные незавершённые части

1. **Полная доставка на текущем заводском `robotio` ещё не реализована до рабочего допуска.** В `DeliveryRobot.blockers()` для ненативного адаптера остаётся безусловная причина «нужен принятый сценарий robotio». `begin()` использует контракт профиля/boot reference нового контроллера. Поэтому одних новых флагов калибровки недостаточно: нужен совместимый принятый исполнитель для текущего адаптера, затем физический сквозной тест. В этом аудите флаги не подставлялись и защита не удалялась.
2. **Ночной самостоятельный учебный цикл не подключён полностью.** В `web.py` провайдер curriculum возвращает пустую очередь, а `training_ready=False`. `AutonomousDay` существует, но расписание само не даёт полноценного цикла обучения. Запись показов и соответствующий координатор LeRobot — отдельные работающие пути.
3. **Не приняты реальные геометрия/удержание/повторная локализация для полного автономного переноса.** На машине `localization_verified=false`, `gripper_calibrated=false`. Принятая геометрия лидаров для картографирования не заменяет hand-eye и проверку удержания предмета.
4. **После сбоя обучения нет автоматического бесконечного retry того же набора.** Ручной повтор теперь работает; координатор показывает сбой и не запускает его циклически. Для автоматического восстановления нужен ограниченный retry с задержкой и отдельной классификацией причин.
5. **Повреждённые локальные JSON-записи требуют более устойчивого восстановления.** В частности, инициализация `MobileDemonstrations` и некоторые чтения `LearningJobs` разбирают сохранённые записи без изоляции ошибки каждого файла. Резкое отключение, ручная порча или неисправность диска не должны выводить весь веб-сервис из строя. Нормальные записи пишутся атомарно, но это не устраняет все случаи повреждения.

Эти пункты не называются отсутствием «идеальной прошивки» и не оправдывают снятие реальных проверок. Это конкретные программные и физические зависимости. Аудит не подтвердил полную автономную доставку.
