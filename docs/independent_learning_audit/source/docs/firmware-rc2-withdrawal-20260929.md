# Отзыв Explorer STM32 0.2.3-rc2

Образ SHA256 `82876334d0cda002388dafdd058dcf084031847dc7d408f2f1e3684295f408f9` не устанавливать. Разрешение пользователя получено, однако повторная проверка до записи выявила дефект. В этом сеансе запись, стирание, GO и сброс контроллера не выполнялись.

## Подтверждённые ошибки

1. Предыдущий вывод об отсутствии штатного sync write неверен. В оригинальном `milo-final/firmware/m3pro-v4/APP/app_arm6.c:90–126` функция `Arm_Sync_Write` формирует 38-байтовый пакет `FF FF FE 22 83 2A 04` с шестью ID, big-endian положением/временем и контрольной суммой. Именно такой формат используется установленной 0.2.2-rc1. Это опровергает объявленную причину неисправности, но само по себе не доказывает, что все передачи на реальном проводе выполняются правильно.
2. В исходниках rc2 `firmware/src/servo_bus.c:125` отбираются только суставы со свежим измерением; строки 137–140 затем безусловно включают torque широковещательно для всех. Сустав с отсутствующим измерением может получить питание со старой целью. Этот образ не прошёл необходимую проверку безопасности.
3. Формулировки README rc2 «физически проверенный формат» и гарантия отсутствия стартового рывка не подтверждены. Пять компьютерных тестов и воспроизводимость сборки не заменяют аппаратную приёмку.

## Что известно и что неизвестно

До перехода в BOOT установленная 0.2.2-rc1 возвращала положения шести суставов; малый тест движения не показал ожидаемого изменения. ACK команды и счётчик отправок не доказывают выполнение суставом. Состояние torque и регистры целевого положения непосредственно не измерялись. Причина отсутствия движения пока не установлена.

Установленный протокол Jetson–STM32 не предоставляет произвольную передачу на шину сервоприводов или чтение регистра torque. Поэтому передать такую диагностическую команду одним изменением Python-драйвера через текущий документированный интерфейс нельзя. Это не доказательство необходимости ещё одной прошивки: сначала требуется достоверная локализация причины.

Загрузчик не ответил на два диагностических запроса через Jetson. Сервисы explorer-control, explorer-watchdog и explorer-mcu остановлены; они не были перезапущены в BOOT. Последний установленный образ: 0.2.2-rc1, SHA256 `2ec6c7c4ee3826e5733e359671d4403cb21b21a799c18172718feed7d07fad56`.

## Следующий шаг

Вернуть BOOT в обычное положение и один раз сбросить контроллер без извлечения платы. Начать с чтения идентификации и датчиков без команд движения. Не выполнять повторную запись по прежнему согласию; любой новый образ требует отдельной проверки и согласования хэша. rc2 исключён из подготовленного обновления Jetson, бинарные файлы сохранены как доказательства.

## После RESET по подтверждению пользователя

29.09.2026 связь с 0.2.2-rc1 восстановлена. Четыре секунды чтения, без OPEN/ARM/BASE: 1560 ответов серв, 200 STATUS, 399 IMU, 440 пакетов LIDAR0 и 437 LIDAR1, 8 записей батареи. Ошибок парсера нет. Последние положения ID 1–6: 2001, 1100, 3588, 2922, 1486, 1265; ошибки устройств нулевые. arm_enabled=false; PWM, цели и измеренные скорости четырёх колёс равны нулю. Лог: `data/firmware-release-20260929/post-reset-readonly-1790671120649104121.json`.

Прямой захват Logitech снова работает; получен свежий кадр неподвижного робота. Команды движения в этом продолжении не отправлялись. Версия 0.2.2-rc1 подтверждена идентификацией контроллера; полного чтения flash после RESET не делалось.

Из рабочего исходника firmware удалены ровно шесть изменений отозванного rc2: перед заменой подтверждено, что они совпадали с архивом rc2, а HEAD совпадал с архивом установленного rc1. Архив rc2 и полный diff сохранены. Пять групп CTest проходят. Это возврат исходников к проверяемой базе, не исправление физического исполнения руки.

Отдельно скомпилирована функция Arm_Sync_Write из сохранённого исходника производителя и сравнивалась с реальной ex_servo_make_sync: 10000 наборов положений, runtime 0/100/500/2000; все 38 байт совпали во всех случаях. Исходник сравнения, SHA исходного файла и результат: `data/firmware-release-20260929/vendor-comparison/`. Проверка не измеряет сигнал на физической шине.

В тестовом скрипте Jetson убраны повтор отклонённой команды, откат номера последовательности и продление срока старой команды. Успех сопоставляется по операции и sequence; ACK и свежий опрос не выдаются за достигнутую цель. Три теста политики диспетчера проходят. Скрипт установлен на Jetson, но для нового движения не запускался. Сервисы mcu/control/watchdog возвращены в работу с прежним telemetry_only=true; флаги аппаратной приёмки не изменены.

Неподтверждёнными остаются состояние torque и принятие целевого регистра самим приводом. Эти данные отсутствуют в установленном протоколе. Это точное ограничение текущей диагностики, а не доказанная причина отказа. По этим результатам новый образ не собран и не предложен к записи.
