# Автоматический запуск навигации

При критическом/неизвестном питании Nav2 остаётся в ожидании и не загружает
тяжёлые серверы. Проверяется свежий `status.json`/`power.json`, фактическое
напряжение относительно существующего порога остановки и настоящее состояние
политики питания. Повышение напряжения само по себе не снимает сохранённый
`CRITICAL`; используется штатная логика восстановления. Потеря допустимого
питания во время работы завершает запущенную группу серверов. Конфигурация
питания и ограничения движения при этом не меняются.

При загрузке или возвращении контроллера Explorer ждёт настоящую свежую
одометрию, IMU, оба лидара и доступную систему координат карты. Затем запускает
Nav2 и проверяет, что его серверы действительно активированы. Состояние
`active` у службы Linux само по себе готовностью навигации не считается.

Исправлена наблюдавшаяся ошибка: Nav2 запускался раньше появления `odom` и
`map`, прекращал активацию и оставался неработающим при внешне живой службе.
Теперь позднее подключение контроллера не требует ручного перезапуска Nav2.
Если активация не завершилась, сервер завершился или данные пропали надолго,
перезапускается принадлежащая этой службе группа серверов. Прежняя задача
движения не отправляется повторно. Краткая задержка датчика не перезапускает
сервисы, а ограничения свежести в основном управлении продолжают действовать.

Это подготовка программ, а не подтверждение механической калибровки. Допуски
контроллера, геометрия, проверка руки и ограничения основного управления не
изменяются. Подключение контроллера само по себе не выдаёт команды движения.

Основные файлы: `src/navigation_service.py`, `src/navigation_health.py`,
`src/navigation.launch.py`, `src/planning.launch.py`, `config/navigation.yaml`,
`config/planning.yaml`, `systemd/explorer-navigation.service`,
`systemd/explorer-planning.service`.

Текущее состояние записывается в `data/navigation-health.json` и
`data/planning-health.json`: `stage`, `waiting_on`, `lifecycle`, `at`.
Проверить входы без запуска/остановки серверов можно на Jetson:

```bash
source /home/vlad/Explorer/bin/env.sh
python3 /home/vlad/Explorer/src/navigation_service.py navigation --check-only --timeout 10
```

DWB уже настроен для движения вперёд/назад, вбок и поворота; в картах
препятствий используются оба настоящих лидара. В глобальную карту добавлен
контроль регулярного поступления обоих сканов, аналогичный локальной карте.

Обработка стадий Nav2 сверена с официальным исходником
[Lifecycle Manager для Jazzy](https://api.nav2.org/nav2-jazzy/html/lifecycle__manager_8cpp_source.html)
и [активацией costmap](https://api.nav2.org/nav2-jazzy/html/costmap__2d__ros_8cpp_source.html).
Компьютерные проверки покрывают позднее подключение, неактивные серверы,
потерю/возвращение данных, ошибочные часы и адресную остановку собственной
группы процессов. Физическую поездку эти проверки не заменяют.
