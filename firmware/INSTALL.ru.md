# Установка Explorer STM32 0.2.0 — стендовый выпуск

Этот выпуск содержит новое приложение всех используемых функций платы, а не
исторический V4 или переименованный CURRENT. Сборка и компьютерные тесты
проверяются до упаковки. Аппаратная приёмка начинается после установки:
проверить её без записи и запуска нового приложения на плате невозможно.

По текущему поручению сначала устанавливается STM32; интеграция с рабочим
управлением Jetson выполняется следующим этапом. **Прежний micro-ROS agent
и веб-управление не совместимы с новым транспортом. До переключения драйвера
робот не будет управляться через старый интерфейс.**

## Что требуется физически

Колёса должны быть вывешены на устойчивом стенде, рука поддержана так, чтобы
сброс или отказ не вызвал её падения. Не удерживайте колёса и суставы руками.
Подключите USB-C **данных контроллера** к Mac кабелем с передачей данных.
Убедитесь, что плата получает штатное питание. Это не разъём питания Jetson.

Для входа в загрузчик: удерживая BOOT, нажмите и отпустите RESET, затем отпустите
BOOT. Эта последовательность — инструкция Yahboom для платы; это реальный
сброс контроллера. Приложение робота в загрузчике не работает.

Источник производителя:
https://www.yahboom.net/public/upload/upload-html/1755253798/4.Burning%20STM32%20firmware%20using%20serial%20port.html

## Команды в Terminal на Mac

Python 3.9+ и STM32CubeProgrammer уже имеются на этом Mac. Откройте распакованную
папку пакета в Terminal. Сначала проверьте файлы и найдите порт:

```sh
python3 install.py verify
python3 install.py ports
```

Затем выполните **точную команду из `COMMANDS.txt`**, в которой записан полный
SHA256 `explorer-sector0.bin`. Передача `--approve-sha256` означает согласование
именно этого образа; `--bench-ready` означает ваше подтверждение описанной
выше физической подготовки. Эти параметры не являются результатом испытаний.

Если подходящий последовательный порт один, он определяется автоматически.
При нескольких портах добавьте `--port /dev/cu.usbserial-…`, выбрав именно плату
по результату `ports`. Не выбирайте первый попавшийся порт.

Установщик использует режим UART, 115200, чётную чётность, 8 бит, 1 стоп-бит.
Он не использует ST-LINK, не делает reset/GO, не меняет option bytes/RDP.
Чтение обоих банков до и после записи может занять несколько минут.

## Проверки перед первой записью

1. Хэши всех файлов пакета, таблица векторов и границы приложения.
2. Реальные DBGMCU ID/REV, UID и FLASHSIZE: ID 0x450, ревизия V 0x2003,
   1024 либо 2048 КиБ. Строка программатора «2 MBytes (default)» не используется
   как доказательство. У другой ревизии 480-МГц конфигурация не допускается.
3. RDP level 0, SWAP_BANK=0, программный старт IWDG, BOOT_ADD0=0x08000000,
   отсутствие защиты первого сектора. Защиты не отключаются автоматически.
4. Свежая копия **обоих действительных банков**: при 1024 КиБ это 512 КиБ по
   адресу 0x08000000 и 512 КиБ по адресу 0x08100000; при 2048 КиБ — по 1 МиБ.
5. Первый сектор совпадает с первым сектором сохранённого рабочего CURRENT
   `e41e3cf0f8a406e354624cbf6ea15937e4da83d0ec0b9d04f76e16354b08b94c`.
   Повторное чтение этого сектора совпадает; перед записью та же плата/options.

Если любая проверка не прошла, стирание не начинается. Сохраните сообщение и
папку `sessions`; не добавляйте флаги разблокировки или полного стирания.

## Что именно меняется

Приложение связано для 0x08000000 и помещается в первые 128 КиБ.
`application/explorer.elf`, `.map`, `.bin`, `.hex` — результаты компилятора.
`explorer-sector0.bin` — **устанавливаемый полный первый сектор**: новое
приложение плюс неизменённый хвост того же сектора из проверенного CURRENT.
`explorer-sector0.hex` содержит те же 128 КиБ с адресами.

Так сохраняются байты за концом нового приложения, вместо предположения, что
они не используются. За пределами сектора 0 байты не стираются и не пишутся.
Приложение само не пишет настройки во flash и не изменяет EEPROM серв.

Установщик выполняет `-e 0`, затем пишет восемь частей по 16 КиБ через
`--skipErase --download … -v`. После этого оба банка читаются заново:
первый сектор должен точно совпасть с утверждённым образом, все остальные
байты — с копией до установки. Проверяются неизменность UID/options.
Эта схема воспроизводит размеры частей, использовавшиеся ранее с этой платой,
но каждый новый результат чтения проверяется заново.

После сообщения `ЗАПИСЬ И ЧТЕНИЕ ПРОВЕРЕНЫ` отпустите BOOT и нажмите RESET
при подготовленном стенде. Скрипт сам приложение не запускает.

## Восстановление

Если запись прервалась, остаётся `sessions/<дата>/backup.json` и полные файлы
`before-bank1.bin`, `before-bank2.bin`, созданные **до стирания**. Не удаляйте
папку даже при ошибке. Войдите в загрузчик описанным выше способом.

Для восстановления первого сектора выполните команду `restore` из `COMMANDS.txt`,
указав папку соответствующей сессии в `--backup`. Установщик проверит UID,
options, хэши резервных копий и неизменность остальных секторов, восстановит
первый сектор из **свежего бэкапа этой сессии**, затем сверит оба банка целиком.
При отличиях вне первого сектора он остановится, не стирая другие области.

Если запись прервалась после стирания, кнопка RESET с обычным BOOT сама по себе
не восстановит программу: нужен `restore`. Автоматических повторов стирания нет.

## Граница проверки

В комплекте есть исходники, закреплённые зависимости, журналы сборки,
результаты компьютерных тестов и сравнение повторных сборок. Нет результатов
реального запуска, измеренной задержки остановки, физической калибровки
PID/суставов или выполненной доставки. `hardware_accepted=false` сохраняется.

Порядок приёмки: отсутствие самодвижения после включения → оба лидара, IMU,
батарея, энкодеры и сырые ответы шести серв → направления на стенде → истечение
команд, остановка процесса Jetson, потеря связи и восстановление → плавная
траектория руки с измеренной позой → совместная работа → движение по полу.
Не отключайте USB у свободно едущей машины.

Отрицательное измерение сохраняется; обычное движение вне заданных рабочих
пределов не разрешается. Возврат оттуда требует отдельного проверенного
коридора. Ограничение рассогласования текущей цели и измерения 0,15 рад
не добавляет остановок на промежуточных точках и не заменяет траекторию MoveIt.
Отсутствие ответа сустава не считается достижением цели.

Подписанные координаты вычисляются на Jetson по явной калибровке; в STM32 она
передаётся отдельно и проверяется. Старт STM32 только опрашивает руку, не
переводит её в HOME и не отключает удерживающий момент.
