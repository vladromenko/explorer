# Explorer STM32 0.2.0 — стендовый выпуск

Полное приложение STM32H743: четыре мотора с энкодерами, рука, два лидара,
IMU, батарея, RGB и зуммер. Пользователь установил ранний образ a69d32…;
Jetson уже использует совместимый native-драйвер вместо micro-ROS agent.

Текущие исходники дополнительно содержат исправления запуска датчиков,
паузы шины руки и ограниченных повторов чтения. Они собраны и проверены
на компьютере, **но не установлены и не приняты на физической плате**.
Последнее ограничение пользователя запрещает повторную запись; сборка
не даёт разрешения на установку. Не подменяйте текущую рабочую резервную
копию этим кандидатом.

Замороженный кандидат и результаты воспроизводимости находятся в
`releases/Explorer-STM32-arm-retries-NOT-INSTALLED-20260929` основного проекта.
Физические результаты текущего установленного образа — в
`docs/CONTROLLER-ACCEPTANCE-20260929.ru.md`.

## Сборка

Из корня Explorer: `python3 firmware/tools/build.py --target all`.
Из папки исходников в архиве: `python3 tools/build.py --target all`.
Нужны CMake, компилятор C для компьютерных тестов и GNU Tools for STM32
14.3.rel1.20251027-0700 (GCC 14.3.1). На этом Mac сборщик находит инструменты
в STM32CubeIDE; иначе передайте `--toolchain /path/to/bin`.
`--output-root /path/to/another-directory` позволяет независимо повторить
сборку. Проверены побайтово одинаковые BIN, HEX и ELF в разных папках.
В последней независимой повторной сборке MAP также совпал побайтно.

Зависимости Yahboom/ST сохранены в `vendor/`, происхождение и исходные хэши
записаны в `sources.json`. Сборка не открывает порты устройства.
Результаты: `build-stm32/explorer.elf`, `.map`, `.bin`, `.hex`, `SHA256SUMS`,
`build-result.json`, `build.log`. Идентификатор исходников встроен в приложение
и записан в `build-stm32/generated/source.sha256`.

## Что реализовано

- Независимый моторный цикл 100 Гц в TIM6; UART, датчики и вычисления Jetson
  не являются его планировщиком. Энкодеры считываются аппаратными счётчиками.
- Локальное истечение команд не позднее следующего моторного цикла после
  срока (максимальная аренда 250 мс). Отдельные finite end, HOLD и CANCEL.
  Реальная задержка физической остановки ещё должна быть измерена.
- Boot nonce, монотонные session/sequence, отказ от старых/повторных команд,
  отдельный сброс ошибки и новая сессия. Нет автоматического возобновления.
- IWDG питается только после нового завершённого цикла управления и прохода
  основного цикла. Зависание одного из них прекращает питание watchdog.
- Один исполнитель шины руки; старт только читает положение, не посылает
  HOME или torque-off. Реальные ответы и ошибки публикуются по суставам.
- Отрицательное измерение не маскируется. Рабочие пределы и отдельно заданный
  коридор возврата проверяются независимо; калибровка обновляется атомарно.
- Непрерывные дробные цели с runtime=0, без обязательного ожидания на каждой
  точке. Интерполяция полной траектории принадлежит исполнителю Jetson.
  Рассогласование цели и измерения ограничено 0,15 рад, без расширения
  механических пределов. Физическая пригодность частоты 50 Гц ещё не принята.
- Потеря ответа одного сустава не задерживает удержание остальных свежих
  суставов. Частичное удержание не выдаётся за полную остановку руки.
  Подтверждение относится к конкретному поколению цели/отмены.
- Обе линии лидара передают проверенные сырые пакеты; IMU и ADC возвращают
  статус ошибки отдельно от измерения. Invalid encoder data не публикуются
  драйвером как новая корректная одометрия.
- UART FIFO сохраняет байты во время приоритетного моторного IRQ. RGB
  передаётся SPI DMA, чтобы прерывания не ломали временную диаграмму WS2812.

## Аппаратное соответствие исходникам производителя

| Функция | Настройка |
|---|---|
| MCU/тактовая частота | STM32H743 rev.V, 480 МГц, HSE 25 МГц; другая ревизия отвергается |
| Jetson | USART1 PA9/PA10, 2 000 000, 8N1 |
| Рука | USART3 PD8/PD9, 115 200, 8N1; запрос FF FF, ответ FF F5 |
| Лидар 0 / 1 | UART4 PC10/PC11; UART5 PC12/PD2; 230 400 |
| Моторы | TIM1 M1/M2; TIM8 M3/M4; драйвер из Yahboom Motor |
| Порядок FL/FR/RL/RR | M1/M3/M2/M4; энкодеры TIM3/TIM5/TIM2/TIM4 |
| Знаки энкодеров FL/FR/RL/RR | + / − / + / −, по примеру производителя |
| IMU | SPI2 PB13, PC2_C, PC3_C, CS PB12, ICM20948 |
| Батарея | PC0, ADC1 channel 10; напряжение, не кулонометрический SOC |
| RGB | SPI4 PE2/PE6, 8 светодиодов; DMA2 Stream0, request 84 |
| Зуммер | PE5 |
| Отладочный UART | UART7 PE7/PE8, 115 200 |
| OLED | Обслуживается Jetson; прошивка STM32 не меняет его проводку |

Константы геометрии и PID — исходная настройка по материалам производителя,
а не новая физическая калибровка конкретного шасси.

## Память и доказательства

FLASH приложения: 48 336 байт, размещение только 0x08000000–0x0801FFFF.
DTCM: 75 400 байт вместе с резервом стека 16 КиБ, 0x20000000–0x2001FFFF.
Для RGB DMA: 224 байта в выделенном диапазоне 0x30000000–0x300003FF.
D-cache выключен, DMA не обращается к DTCM. Две повторные сборки совпадают.

Три группы C-тестов прошли с ASAN/UBSAN: расчёт/сроки управления, протокол
и атомарные переходы, настоящий диспетчер серв с подменённым только UART/HAL.
Тесты включают миллион случайных байтов, отрицательные положения, отказ одного
сустава и повторные поколения остановки. Семь тестов установщика проверяют
неподходящую плату, неверный хэш, изменённый CURRENT, смену UID, обрыв после
стирания и точное восстановление, используя память компьютера вместо платы.

Компьютерные тесты **не проверяют** реальную разводку конкретного экземпляра,
наличие ответов серв, пределы движения, полярность IMU/лидаров, задержки
торможения или доставку носка. Протокол приёмки приведён в `INSTALL.ru.md`.

## Установка и восстановление

См. `INSTALL.ru.md`. Пакет `releases/Explorer-STM32-0.2.0-bench1` содержит
устанавливаемый сектор, исходники, ELF/MAP/BIN/HEX, manifest, хэши, тесты,
точные команды и установщик. Установщик проверяет реальный размер и карту
flash, сохраняет оба банка и меняет только первый сектор с последующей
проверкой всей flash. Хвост сектора за приложением сохраняется из CURRENT.
Скрипт восстановления использует свежий бэкап той же платы и той же сессии.
Mass erase, смена option bytes и автоматический запуск не используются.

Встроенный идентификатор исходников и SHA256 образа не являются флагом
аппаратной приёмки. `hardware_accepted=false` сохраняется до физических тестов.
